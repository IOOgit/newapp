# Универсальный мониторинг коммутаторов — 2.12.0

## Что изменено

Существующий раздел коммутаторов расширен без отдельного приложения. Модель
устройства — свободный текст; суффиксы сохраняются. Надпись о невозможности
SNMP для определённой модели и миграция, очищавшая её настройки, удалены.
Тема Industry, общая навигация, CSS-переменные, кнопки, таблицы, шрифты и
модальные окна сохранены. Новые CSS-правила ограничены компоновкой раздела.
Цвета статусов соответствуют существующей монохромной палитре; состояние
подписано текстом и доступно с клавиатуры.

## Поток данных

APScheduler использует прежнюю задачу `switch_poll`: фиксированное количество
async workers опрашивает включённые устройства. Ручной опрос и проверка формы
поступают в ограниченную очередь и используют тот же семафор. HTTP возвращает
202 и ID задания сразу; страницы и GET API читают БД, не выполняя SNMP.
Задание проверки доступно только создавшему его пользователю. Одновременное
редактирование и опрос одного сохранённого устройства запрещены.

TCP и SNMP опрашиваются независимо. Любой подтверждённый ответ означает,
что устройство онлайн. Ошибка SNMP при успешном TCP отображается отдельно.
Возможности определяются ответами OID. Имя производителя по PEN из реестра
IANA — только подпись; неизвестный PEN не ограничивает мониторинг.

Секрет поступает только во входном запросе, шифруется существующим Fernet,
не возвращается в обычном API/HTML, не попадает в ошибки валидации или логи.
В резервную копию входит зашифрованное значение. В логах — ID и код ошибки,
без сырого исключения транспорта. Повторяющиеся ошибки записываются только
при изменении состояния/причины. SNMP SET не используется.

## Стандартные MIB

- SNMPv2-MIB: sysDescr, sysObjectID, sysName, sysUpTime.
- IF-MIB: ifTable и ifXTable, включая ifIndex, ifName/Descr/Alias,
  ifConnectorPresent, MAC, admin/oper, speed/highSpeed, LastChange,
  HC/32-bit octets, errors, discards, CounterDiscontinuityTime.
- BRIDGE-MIB: сопоставление dot1dBasePort → ifIndex.
- ENTITY-MIB: chassis, производитель, модель, firmware; наличие fan/PSU.
- ENTITY-SENSOR-MIB: допустимые числовые измерения со scale/precision,
  в том числе температура; невалидные измерения не показываются.
- POWER-ETHERNET-MIB: состояния PSE-портов, ошибки, классы нагрузки,
  использованная мощность и номинальная мощность PSE-групп.
- LLDP-MIB, Q-BRIDGE-MIB и таблица MAC: определение наличия данных.
  Детальные таблицы соседей/VLAN/MAC пока не выводятся.

Для v2c discovery использует GETBULK, для v1 — GETNEXT. Регулярные измерения
запрашивают только обнаруженные динамические OID пакетами до 24 переменных.
Есть fallback при tooBig/некорректной поддержке GETBULK, обработка v1
noSuchName без потери остальных OID и ограничение размера walk.

Инвентаризация кэшируется на 6 часов, обновляется при изменении ifNumber,
sysObjectID, настроек или снижении uptime, не объясняемом оборотом TimeTicks.
Отсутствие необязательной MIB не отменяет базовые данные. Таймауты optional
MIB ограничены отдельным бюджетом, весь опрос — общим deadline.

## Достоверность показателей

RX/TX = разность октетов × 8 / время между измерениями. Предпочтительны
Counter64. Первая точка, пропуск опроса, перезагрузка, discontinuity,
смена ширины счётчика и неправдоподобные скачки дают «—». Для Counter32 при
интервале, допускающем несколько оборотов на скорости порта, результат также
неизвестен: уменьшите период или используйте агента с Counter64.

Снижение счётчика без discontinuity считается оборотом только у границы
диапазона и при физически допустимой дельте. Старый агент без счётчика
разрывов не позволяет идеально отличить все возможные сбросы от оборота.

Физический порт определяется ifConnectorPresent; для старых агентов —
Ethernet ifType и именем интерфейса. Полный список включает логические и
неопределённые интерфейсы. Номер на корпусе не выводится из ifIndex.
При смене имени на прежнем ifIndex ручная привязка сбрасывается с событием.
Суммарный трафик — сумма физических портов, включая оба конца пересылаемого
потока; это не скорость внешнего uplink. Если части слагаемых нет, сумма «—».

PoE index `group.port` не приравнивается к ifIndex. Пока нет документированного
автоматического соответствия, оператор выбирает его в карточке порта.
RFC 3621 не задаёт фактические ватты каждого PSE-порта: эти поля остаются
пустыми, а класс PD не выдаётся за измеренное потребление.

Vendor adapters пока **не добавлены**: нет проверенных vendor MIB/walk.
Есть интерфейс расширения и реестр по sysObjectID prefix. Адаптер дополняет
стандартный снимок; его ошибка не отменяет уже полученные стандартные данные.

## История и настройки

| Параметр | По умолчанию |
| --- | --- |
| `SWITCH_POLL_SECONDS` | 30 с, system/порты/трафик/PoE одним циклом |
| `SWITCH_POLL_TIMEOUT_SECONDS` | 30 с на SNMP-сбор устройства |
| `SWITCH_MAX_CONCURRENT_POLLS` | 4, общий предел фоновых и ручных проверок |
| `SWITCH_DISCOVERY_SECONDS` | 21600 с |
| `SWITCH_TELEMETRY_SECONDS` | 60 с |
| `SWITCH_TELEMETRY_DAYS` | 3 дня |
| `SWITCH_EVENT_DAYS` | 30 дней |

Снимок включает агрегаты и компактные метрики портов вместо отдельных OID.
UI показывает агрегированный график последних суток. События online/offline,
port up/down/removal, смены идентичности порта, PoE fault, начала роста ошибок
и перезапуска создаются на переходах; непрерывный рост ошибок не спамит ленту.
Долгосрочные rollup-таблицы, SNMPv3 и trap receiver в этой версии отсутствуют.
Граница транспорта и обработка снимков позволяют добавить их отдельно.

## Миграция и развёртывание

Новые колонки добавляются штатным `_NEW_COLUMNS`, таблицы — create_all.
Если в старой схеме отсутствовал management_port, TCP-порт переносится из
snmp_port только для прежних записей `snmp_version=none`; SNMP получает 161.
Настоящие SNMP-порты и зашифрованные community прежних записей сохраняются.
Повторный старт не меняет настройки. Старые JSON-бэкапы преобразуются при
импорте тем же способом. Перед обновлением сохраните БД и ключ шифрования;
при откате к старому коду восстановите соответствующую старую БД.

Новая зависимость: `pysnmp==7.1.22`. После получения ветки:

```bash
docker compose up -d --build app
docker compose logs --tail=100 app
```

Запускайте один процесс приложения с планировщиком, как в текущем Dockerfile:
очередь, блокировки и задания живут в памяти процесса. Для нескольких процессов
потребуется внешний worker/распределённая блокировка.

## Проверки и первый реальный запуск

Автоматические проверки покрывают discovery неизвестного производителя,
PEN-подписи, отсутствие PoE, частичные таблицы, несмежные ifIndex, физические
интерфейсы, единицы датчиков, 32/64-bit counters, обороты/сбросы/перезапуск,
таймаут/auth error, события и дедуп, независимость TCP, лимиты воркеров,
секреты, XSS, фоновый 202 API, retention и миграцию старой SQLite-схемы дважды.
UDP-эмулятор проверяет настоящий BER-обмен PySNMP v1/v2c, Counter64 > 2^63,
noSuchName и неверную community. Визуальная проверка — Chromium, 1440 и 390 px,
28 и 52 порта, вкладки, модальные окна и кнопка проверки.

Исходная ветка имела 284 успешных теста и один устаревший тест `quality`.
Он приведён к уже удалённой функциональности; работающий код NVR не менялся.

После объединения с существующей веткой `codex/ntp-time-sync` итоговый прогон:
**339 passed** (`TZ=UTC python -m pytest -q`); до объединения — 321.
Настройки NTP, ежедневное расписание и кнопка на дашборде сохранены. В локальном
часовом поясе среды около границы суток старый `test_buses::test_not_collected`
падает также на исходном коммите: сравниваются naive UTC из SQLite и локальная
дата. Код автобусов в этой задаче не изменён; полный прогон выполнен в UTC.

Реальный DES-1210-28P из этой среды недоступен; его MIB/прошивка не проверены.
После установки на сервер с маршрутом до коммутатора:

1. Укажите его адрес, включите v2c, задайте read-only community и нажмите
   «Проверить SNMP». Community/ACL настройте на самом коммутаторе.
2. Сохраните и дождитесь двух опросов или выполните два ручных опроса с паузой.
3. Сверьте ifName/ifDescr, число физических портов, up/down и скорости с веб-UI.
4. Сверьте PoE-группы/бюджет, если они обнаружены. Недоступная MIB — «—».
5. Проверьте штатный переход состояния безопасного тестового порта и событие.

PostgreSQL используется существующими ORM/DDL-паттернами проекта; отдельный
живой PostgreSQL для этой сессии не запускался. Миграционный тест выполнен на SQLite.
