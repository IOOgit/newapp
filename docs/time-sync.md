### NTP и ежедневная синхронизация регистраторов

На дашборде откройте **Настройки времени**. Укажите IP/домен NTP-сервера,
UDP-порт (обычно 123), время ежедневного запуска и часовой пояс IANA.
Для Хабаровска — `Asia/Vladivostok`. Нажмите **Проверить NTP**, затем включите
расписание и сохраните настройки. Доступ соответствует праву «Мониторинг».

Сервер приложения запрашивает NTP и выставляет полученное время через API
всех включённых NVR; отключённые устройства пропускаются. Это не установка
адреса NTP непосредственно в настройках NVR. Часовой пояс в форме применяется
к расписанию и передаваемому локальному времени: выбирайте пояс регистраторов
(особенно Dahua, чей API принимает время без смещения).

Существующие ручные команды, массовая синхронизация и команда бота тоже
используют сохранённый NTP-сервер. Если адрес пуст, ручные команды сохраняют
прежнее поведение — время компьютера приложения. Расписание требует NTP.
При ошибке NTP автоматического перехода на часы компьютера нет.

Настройки и результат последнего запуска по расписанию сохраняются в БД.
Ошибки отдельных NVR не прерывают остальные устройства; ошибка NTP отменяет
весь запуск. На странице доступны следующий запуск и результаты по устройствам.
Настройки расписания применяются без перезапуска. Во время работы приложения
пропущенный из-за задержки планировщика запуск допускается в пределах 5 минут;
запуски за время остановки приложения не воспроизводятся при старте.

Запускайте приложение с одним процессом Uvicorn (как в штатном Dockerfile):
планировщик находится внутри процесса. Браузер можно закрыть, сервер приложения
должен работать и иметь UDP-доступ к выбранному NTP-серверу. Проверка NTP
ограничена 8 секундами; время отправляется устройствам с учётом длительности
массового прогона. Синхронизация не гарантирует одновременную установку часов
на всех NVR. После обновления необходимо проверить работу на реальном NVR:
автотесты используют mock API и имитацию NTP-пакетов.
